# CLOUD-C18b — Own-account watch (opt-in schedule, audit, "what changed")

- **Opt-in:** `startWorker` calls `applyWatchSchedule`: schedules `schedule-collect` only when `ZEREF_WATCH_ENABLED=1`, otherwise `unschedule`s it. Interval default 4 h (`ZEREF_COLLECT_INTERVAL_HOURS` overrides, clamped 1–24; 24 → `0 0 * * *`).
- **Watch run** (`apps/worker/src/jobs/watch-run.ts`, `runWatch`): disabled → `skipped_disabled` (schedule + task_scheduler; `on_demand` is allowed while disabled), no token → `skipped_no_token`, `pg_try_advisory_lock` held → `skipped_locked`. Otherwise inserts a `running` row, then: debug_token expiry (only with `INSTAGRAM_APP_TOKEN`, at most once per UTC day, warns < 7 days), recent-media window (`/me/media?limit=12`, 1 call), collect newest own media id (env `ZEREF_COLLECT_SHORTCODES` / `ZEREF_COLLECT_GRAPH_MEDIA_ID` still win), diff, finish row.
- **Budget:** `ZEREF_GRAPH_DAILY_CAP` (default 200) via a `GraphBudget` seeded from `SUM(graph_calls)` of today's (UTC) `watch_runs`, so it survives restarts. All Graph calls (incl. collect via new `CollectPipelineDeps.graphOptions`) go through it. `GraphThrottledError` → `throttled` + `error_code throttled_<reason>`; the pg-boss handler never throws, so no retries — next tick only.
- **Audit:** migration `0006_c18_watch_runs.sql` (journal idx 6). `error_code` is a fixed code (`graph_http_<status>`, `graph_network`, `no_media`, `internal`, …), never a message. Tokens are never persisted or logged (`redactGraphSecrets`; tests with `SECRET_TOKEN_123`).
- **What changed:** `diff_json` = recent-media window + `newPosts` / `removedPosts` (vs last `ok` run; a post that scrolled out of a full window is not "removed") + per-post diff of the two newest snapshots per `sourceRef` (likes, comments, reach/impressions only when present) with `latestCollectedAt` and `previousCollectedAt`. A collect that dedupes onto an existing snapshot is `unchanged` with no delta.
- **Task Scheduler:** `scripts/watch-collect.ps1` (loads `.env`, enqueues one `task_scheduler` job via `apps/worker/dist/cli/watch-trigger.js`; `-Direct` runs in-process) and `scripts/register-watch-task.ps1` (every 4 h, current user, `-WhatIf`, `-Remove`). Neither prints secrets.
- `runScheduleCollect` (legacy enqueue helper) also resolves the newest media id when no env target is set, instead of failing `CollectJobInputSchema.parse`.
