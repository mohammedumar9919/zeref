# CLOUD-F1 — H2a follow-ups (watch cockpit refresh + insights budget)

- **Cockpit refresh after watch runs:** `runWatch` counts snapshots actually inserted this run (`newSnapshots` on the result; deduped collects don't count) and, only for `ok` runs with ≥ 1 new snapshot, calls `onNewSnapshots` after the run row is finished and the advisory lock is released. `createWatchJobHandler` wires it to `insertCockpitPipelineOutbox(pool, "collect")`, so the payload is identical to a `collect` job completion. Skipped / throttled / error / no-change runs emit nothing; a failing outbox insert is logged (redacted) and does not change the run outcome. `WatchHandlerDeps.runOverrides` is a test seam.
- **Insights under the Graph budget:** `fetchMediaInsights` / `fetchAccountInsights` (incl. the `me` lookup) now go through `graphGetWithErrors` (the `graphGet` core) with `options.graph`, so they consume the budget, report usage, back off on high usage / 429, and redact tokens. Without options, behaviour is unchanged except tokens are redacted: error messages remain the Meta `error.message` or `Graph insights <status>` / `Graph account insights <status>` / `Graph me failed: <status>`.
- **Meta throttle codes:** non-OK responses whose JSON `error.code` is 4, 17, 32 or 613 throw `GraphThrottledError("usage_high")` (Retry-After or usage regain time when present), with or without options — same as HTTP 429. `GRAPH_THROTTLE_ERROR_CODES` exported.
